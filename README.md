# no-magic-viz

Manim-powered algorithm visualizations for the [no-magic](https://github.com/no-magic-ai/no-magic) project.

Every no-magic script gets an animated explainer — showing the algorithm's core mechanics in motion, not just in code.

## Structure

```text
no-magic-viz/
├── scenes/          ← Manim source files
│   ├── base.py      ← Shared base class, color palette
│   ├── scene_microattention.py
│   ├── scene_microgpt.py
│   └── ...
├── previews/        ← GIF previews for README embedding (tracked)
├── renders/         ← Full MP4s (local only, not committed)
├── media/           ← Render scratch space (local only, not committed)
├── assets/          ← Branded video frames
├── scripts/
│   └── render.sh    ← Render script
├── tests/           ← Behavioral tests for render.sh
├── pyproject.toml
└── uv.lock
```

## Setup

```bash
uv sync
```

Rendering also needs these system tools on `PATH`:

| Tool | Needed for |
|------|------------|
| Cairo and Pango libraries | Manim's Cairo renderer (all scenes) |
| `ffmpeg` and `ffprobe` | Decoding and probing every output; GIF palette conversion |
| `gifsicle` | GIF previews (not needed with `--full-only`) |
| `latex` and `dvisvgm` | Only scenes that build LaTeX-backed mobjects (`Tex`, `MathTex`, `DecimalNumber`, `Integer`, `Matrix`, numbered axes, ...) |

`pyproject.toml` declares Python >= 3.10, and `uv.lock` resolves Manim 0.19.1 on Python 3.10 and Manim 0.21.0 on 3.11+. The render pipeline has been verified with CPython 3.12.8, Manim 0.21.0, FFmpeg 9.0.2, gifsicle 1.96, Cairo 1.18.6 and Pango 1.58.2 on macOS; other versions are not verified.

## Rendering

All rendering happens locally before push. CI only runs lint and syntax checks.

```bash
# All scenes (MP4 + GIF)
bash scripts/render.sh

# Single scene
bash scripts/render.sh microattention

# GIF previews only
bash scripts/render.sh --preview-only

# Full MP4s only (1080p60)
bash scripts/render.sh --full-only
```

The mode flag and the scene name may be given in any order (`bash scripts/render.sh microgpt --preview-only`). At most one mode flag and one scene name are accepted; unknown options, unknown scenes, a second scene name or both mode flags exit with status 2 before anything is rendered. The script resolves every path from its own location, so it can be run from any directory.

`scripts/render.sh` renders `scenes/scene_<name>.py` files only. Each must define exactly one top-level class whose name ends in `Scene`, either a `NoMagicScene` or a plain Manim `Scene` subclass. `scenes/no_magic_overview.py` is not a `scene_*` algorithm scene and is not rendered by this script.

| Output | Format |
|--------|--------|
| `renders/<name>.mp4` | Complete scene, 1920x1080, 60 fps |
| `previews/<name>.gif` | Complete scene, 400x225, 10 fps, 128-color palette, optimized with `gifsicle` |

How a render succeeds or fails:

- Every tool the selected outputs need is checked before rendering starts. A missing tool exits with status 1 and changes no files.
- Manim runs with the Cairo renderer into a new staging directory under `media/`, which is removed when the script exits.
- Each output is fully decoded with `ffmpeg -xerror` and probed with `ffprobe` for frames, duration, dimensions and frame rate. Only when every selected output for a scene passes are they moved into `renders/` and `previews/`.
- Any Manim, `ffmpeg`, `gifsicle` or `ffprobe` failure stops the run with status 1. Outputs already published for earlier scenes in the batch stay, and the previous files for the failed scene and all other files are left untouched.
- The MP4 and the GIF of one scene are moved one after the other, so killing the script between those two moves leaves only one of them updated.

## Previews

The GIFs tracked in `previews/` were produced by an earlier version of the render script that kept only an 8-second excerpt starting 5 seconds into each scene. They are not regenerated by this change. Previews produced by the current script cover the complete scene, including the branded start and end frames, so they are longer and larger than the tracked excerpts.

The tracked `previews/microgpt.gif` predates the current layout and contrast of `scenes/scene_microgpt.py` and does not show the current scene source. [`previews/microgpt.gif`](previews/microgpt.gif) (8-second excerpt): the title card "Autoregressive GPT" with the subtitle "Next-token prediction, one step at a time"; then the heading "Transformer Block" over four connected boxes labeled Embed, Attention, MLP and Predict; then the heading "Autoregressive Generation" over five token boxes t, h, o, m, a, with a brace labeled "context window".

## Checks

```bash
uv run --extra dev ruff check scenes/ scripts/ tests/
uv run --extra dev ruff format --check scenes/base.py scenes/scene_microgpt.py tests/
uv run --extra dev mypy --strict -m base -m scene_microgpt
uv run --extra dev mypy --strict tests/
uv run --extra dev python -m unittest discover -s tests
```

`mypy` resolves `scenes/` as its search path (`[tool.mypy]` in `pyproject.toml`), so `base` and `scene_microgpt` are checked as the top-level modules that scenes import at render time. The tests render small scenes with the real system tools listed above.

## Adding a New Scene

1. Create `scenes/scene_<algorithm>.py`
2. Inherit from `NoMagicScene` in `scenes/base.py`
3. Set `title_text` and `subtitle_text` class attributes
4. Implement the `animate()` method
5. Render locally: `bash scripts/render.sh <algorithm>`
6. Inspect the GIF and commit it to `previews/`
